## 1. 회사 이해 (리서치 완료분)

### 무슨 회사인가
Physical AI 시대의 **3D 데이터 인프라**를 만드는 딥테크 스타트업. NVIDIA Inception 공식 파트너사.

- 본사 분당 킨스타워 18F / R&D센터 수정구 / 미국 산호세 오피스
- 젠슨 황 키노트에서 Physical AI 생태계 파트너로 소개됨

### 핵심 제품 TRINIX — 두 갈래
1. **신규 생성**: Text/Image 입력 → AI 분석 → NURBS 기반 고정밀 3D CAD 자동 생성
2. **기존 CAD 변환**: 기업 보유 설계자산 → 관절 구조·물리 특성 부여 → **Sim-Ready 데이터** 전환
   → 자체 개발 **Omniverse Connector**로 Isaac Sim / Cosmos에 연동

### ⚠️ 버전 혼동의 정체 — 문서마다 숫자가 다른 이유

| 어디서 본 숫자 | 실제 의미 |
|---|---|
| GitHub README "Python 3.12" | **`main` 브랜치 = Isaac Sim 6.0용**. 6.0은 Python 3.12 고정. 5.1과 무관 |
| Isaac Lab pip 문서 "Python 3.11" | **Isaac Sim 5.X용** ← 우리가 따를 것 |
| requirements 문서 "Windows 10/11" | 일반 요구사항 — Win10 허용 (단 2025.10.14 지원종료 예고) |
| pip 설치 가이드 "Windows 11" | pip 설치 경로 기준 서술 |

**Windows 10 리스크 대응**: 일단 pip 설치를 시도하고, OS 체크로 막히면 즉시 바이너리 인스톨러 또는 WSL2로 전환.

### ❌ Isaac Sim 6.0.1을 쓰지 않는 이유 (검토 완료)
- *"Isaac Sim 6.0 **Early Developer Release** for GTC'26"* — 정식 릴리스 아님
- 6.0.0/6.0.1 지원은 **Isaac Lab 3.0.0 Beta 2**뿐 (베타)
- GitHub Issue #6200 — 의존성 충돌 보고 (coverage, packaging, numpy, Pillow)
- *"The previous PyTorch-based Core API is **deprecated** in favor of a new Core Experimental API built on Warp"* — 코어 재설계
- 물리 백엔드가 PhysX/Newton 멀티백엔드로 변경

> **면접용 정리**: "5.1로 작업했습니다. 6.0은 Newton 물리 백엔드와 Warp 네이티브로 코어가 재설계되면서 기존 PyTorch Core API가 deprecated 됐고, Isaac Lab 3.0이 아직 베타라 프로덕션엔 안 올렸습니다."

## 3. 설치 절차

### 사전 확인
```bash
mkdir D:\ic
echo test > D:\ic\wtest.txt
type D:\ic\wtest.txt
```
D: 쓰기 권한 확인. 실패하면 다른 드라이브 탐색.

### 1단계 — Miniconda (관리자 권한 불필요)
1. https://repo.anaconda.com/miniconda/Miniconda3-latest-Windows-x86_64.exe
2. 설치 시 **"Just Me (recommended)"** 선택 ← admin 회피 핵심
3. 경로는 기본값(`%USERPROFILE%\miniconda3`) — 본체는 작아서 C:로 충분
4. PATH 추가는 해제해도 됨. 시작메뉴 **"Anaconda Prompt"** 로 실행

```bash
conda create -p D:\ic\env python=3.11 -y
conda activate D:\ic\env
```

> **경로를 `D:\ic\env`로 짧게 잡은 이유**: Windows 260자 경로 제한.
> 공식 문서가 *"On Windows, it may be necessary to enable long path support"* 라고 경고하는데
> long path 활성화는 **admin 권한 필요** → PC방에서 못 켬 → 짧은 경로로 애초에 회피.

### 3단계 — Isaac Sim 설치 (25GB, 오래 걸림)
```bash
python -m pip install --upgrade pip
pip install "isaacsim[all,extscache]==5.1.0" --extra-index-url https://pypi.nvidia.com --cache-dir D:\ic\pipcache
```

### 4단계 — PyTorch (Blackwell 대응)
```bash
pip install -U torch==2.7.0 torchvision==0.22.0 --index-url https://download.pytorch.org/whl/cu128

isaacsim
```
> **첫 실행은 셰이더 컴파일 때문에 수 분 걸린다** (*"The first time loading Isaac Sim may take up to several minutes"*).
> 멈춘 것처럼 보여도 기다릴 것. 동시에 `nvidia-smi`로 VRAM 실측.

## 4. 프로젝트 설계 — 왜 이걸 하는가

### 폐기한 원안과 그 이유

**원안 A. "URDF → USD 자동 변환 스크립트"** → **부분 폐기**

| 문제 | 근거 |
|---|---|
| 이미 원클릭 내장 기능 | `isaacsim.asset.importer.urdf` 익스텐션, `File > Import`로 끝남 |
| **입력 클래스가 회사 문제와 다름** | URDF에는 joint·link·inertia·collision이 **이미 다 있다**. 회사가 푸는 건 *관절 정보가 0인 정적 CAD*에 관절을 부여하는 것 |
| NVIDIA 스펙도 미완 | SimReady Foundation 스펙 원문: *"currently covers basic static props (ones that don't move or articulate)"* → **관절 부여가 이 바닥 최전선이고 그게 엔닷라이트의 해자** |

**원안 D. "에셋으로 씬 구현"** → **후순위**
자소서에 이미 "Isaac Sim 에셋 라이브러리로 실제 환경과 비슷한 씬 구현 + 블렌더/PhysX 파티클(과자봉지)"이 있음 → **기존 이력서와 중복**, 신규 정보량 적음.

### ★ 그러나 A안에서 살려야 할 알맹이 — URDF에 없는 "제어값"

**URDF가 들고 있는 것 (물리적 성질)**
- `<limit lower upper effort velocity>` — 가동범위·최대토크·최대속도
- `<dynamics damping friction>` — 관절 점성감쇠·마찰
- `<inertial><mass><inertia>` — 질량·관성텐서
- `<collision>` 지오메트리, 링크 트리

**URDF에 없어서 사람이 직접 넣어야 하는 것 (액추에이터 제어 모델)**
- **drive stiffness / damping** — 위치제어기 PD 게인
- Drive Type (Position / Velocity / None)
- Natural Frequency / Damping Ratio
- 기어비 · 백래시 · 토크-속도 곡선

**공식 문서 근거**
- URDF Importer 임포트 옵션에 **"Joint Drive Type"**, **"Joint Drive Strength"**, **"Natural Frequency / Damping Ratio"** 가 따로 존재 → URDF에서 읽는 게 아니라 **사용자가 주는 값**
- 튜토리얼 원문: *"increase the natural frequencies of the joints to **reduce oscillations during movement**"*
- 파이썬 예제가 손으로 박아넣음:
  ```python
  drive.strength = 1047.19751
  drive.damping  = 52.35988
  ```
  → **이 숫자는 URDF 어디에도 없다.**

**즉**: 임포트 직후 로봇은 "형상·기구학은 맞지만 제어 특성은 근거 없는 기본값" 상태.
그대로 돌리면 진동/처짐/오버슈트 발생. 산업용·협동로봇일수록 이 값을 제대로 넣는 게 실력.

**정혁의 기존 경험과 정확히 연결됨**
- MotoSim 무빙실러: payload 미반영 → TCP 3mm 처짐 (물리 파라미터 누락이 실기 오차로)
- 이력서: "중력보상으로 관절 추종오차를 **96% 줄임**" (이미 관절 제어값을 잡아본 경험)

## 5. ★ 확정 프로젝트 — 3단계

**컨셉**: 기사의 **서랍 사례**를 그대로 재현한다.
> *"가상에서 높은 힘으로 설정한 서랍이 실제로는 약한 힘으로 열림 → 로봇의 과도한 동작 초래"*

이 한 문장에 **로봇**과 **에셋**이 둘 다 있다. 그리고 공고 직무명이 **Robot Application Engineer** —
TRINIX가 만든 에셋에 **로봇을 붙여 물리가 맞는지 검증하는 사람**이 이 포지션이다.

| 단계 | 내용 | 산출 지표 |
|---|---|---|
| **P1. 로봇 측** | 산업용/협동로봇 URDF 임포트 → drive stiffness/damping을 **직접 설계·주입** → 튜닝 전후 관절 추종오차 측정 | 추종오차 감소 % |
| **P2. 에셋 측** | 관절 0인 정적 서랍장 CAD에 Joint + 질량 + 마찰을 **스크립트로** 부여 (`ArticulationRootAPI`, Revolute/Prismatic Joint, 충돌근사, 물리 머티리얼) | Sim-Ready 변환 성공 |
| **P3. 결합 검증** | 로봇이 서랍을 연다 → **서랍 물성값을 틀리게 넣으면 로봇 거동이 어떻게 깨지는지** 정량화 | 물성 오차 → 거동 오차 민감도 |

### 왜 이 설계인가
- **P1**이 정혁의 강점(산업로봇·payload·추종오차)이 가장 크게 먹히는 구간 → **여기부터 시작**
- **P2**가 TRINIX 핵심 문제와 1:1 대응 (NVIDIA 스펙도 아직 못 덮은 영역)
- **P3**가 기사의 *"기준이 없다"* 는 공백을 정면으로 침 → **숫자가 나온다**
- 각 단계가 독립 완결 → 자소서의 **"단계별 독립 검증"** 원칙과 일치
- P1만 끝나도 포트폴리오, P3까지 가면 회사 제품 루프의 축소판

### 스코프 경계 (중요)
**에셋은 딱 1개.** 서랍장 하나.
그 이상 욕심내면 자소서가 인정한 단점("완결 욕심에 초기 속도 저하")대로 아무것도 못 끝낸다.
